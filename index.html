Authentication

API Keys

All client endpoints are authenticated via an API key passed in the request header.

How to authenticate

Every request must include your API key in the x-api-key HTTP header. You can find your key in the LinkTrace dashboard under Settings → API Keys.

HTTP Header 
x-api-key: lt_live_xxxxxxxxxxxxxxxxxxxx
⚠
Keep your API key secret. Never expose it in client-side JavaScript, mobile app binaries, or public repositories. Rotate it immediately from the dashboard if you suspect compromise.

Event Ingestion

Tracking Custom Events

Custom events let you measure actions in your app — purchases, sign-ups, level completions, anything meaningful — and attribute them back to the referral link that drove the install.

★
Scale plan required Event ingestion is available on the Scale plan only. Calls from non-Scale accounts return 403 PLAN_UPGRADE_REQUIRED.
POST
/api/v1/events
Ingest a named event against a referral link's short code. Writes are fire-and-forget — the endpoint responds immediately and the database write happens asynchronously.
Scale x-api-key
Request headers
HeaderRequiredDescription
x-api-key Required Your LinkTrace API key.
Content-Type Required Must be application/json.
Request body
FieldTypeRequiredDescription
linkShortCode string Required The 4–32 character alphanumeric short code of the referral link (e.g. 497b3422).
eventName string Required A snake_case event name. Must start with a letter and contain only lowercase letters, digits, and underscores — max 128 characters. Names are normalised to lowercase automatically.

Reserved names (rejected): click, install, impression, open.
entityId string Optional A unique identifier for the entity this event represents (e.g. an order ID, user ID, session ID). When provided, LinkTrace deduplicates events: if the same (linkShortCode, eventName, entityId) tuple has already been recorded, the second call returns 200 { deduplicated: true } instead of writing a new row. Max 255 characters.
Basic — no dedup
JSON 
{
  "linkShortCode": "497b3422",
  "eventName": "web_link_click"
}
With entityId — deduplication enabled
JSON 
{
  "linkShortCode": "497b3422",
  "eventName": "purchase",
  "entityId": "order_9876"
}
Responses
202
Accepted Event queued for async write. Normal success path. 
{ "success": true, "queued": true }
200
Deduplicated Same (shortCode, eventName, entityId) already recorded. 
{ "success": true, "deduplicated": true }
429
Quota exceeded Monthly limit of 5,000 events reached. 
{ "code": "QUOTA_EXCEEDED",
  "resetsOn": "2026-07-01T00:00:00.000Z" }
403
Plan upgrade required Account is not on the Scale plan. 
{ "code": "PLAN_UPGRADE_REQUIRED" }
ℹ
Quota applies to production events only. The 5,000 monthly limit tracks only events sent for the production environment. The counter resets on the 1st of each calendar month (UTC). You can monitor remaining quota with GET /api/v1/analytics/events/quota.
Code example
cURL 
curl -X POST https://api.linktrace.in/api/v1/events \
  -H "x-api-key: lt_live_xxxxxxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "linkShortCode": "497b3422",
    "eventName": "purchase",
    "entityId": "order_9876"
  }'

Analytics

Link Performance & Funnel Analytics

Query click counts, install attribution, and full conversion funnels across your referral links.

GET
/api/v1/analytics/referral-links
Paginated list of all your referral links with aggregated click and install totals.
x-api-key
Query parameters
ParameterTypeRequiredDescription
page integer Optional Page number, starting from 1. Defaults to 1.
limit integer Optional Results per page. Defaults to 20, max 50.
status string Optional Filter by link status: active or inactive. Omit to return all.
Example request
cURL
curl "https://api.linktrace.in/api/v1/analytics/referral-links?page=1&limit=20" \
  -H "x-api-key: lt_live_xxxxxxxxxxxxxxxxxxxx"
Response — 200 OK
FieldTypeDescription
links array Array of link objects. Each object contains all link fields plus referralLink, totalClicks, and totalInstalls.
links[].totalClicks integer All-time click count for this link.
links[].totalInstalls integer All-time attributed install count for this link.
pagination.page integer Current page number.
pagination.limit integer Results per page.
pagination.total integer Total number of links across all pages.
pagination.pages integer Total page count.
GET
/api/v1/analytics/links/:shortCode/funnel
Returns a full conversion funnel for a single link: clicks → attributed installs → custom events. Supports custom date ranges. Scale plan accounts additionally receive a per-event breakdown with install-to-conversion rates.
x-api-key
Path parameter
ParameterTypeDescription
shortCode string The short code of the referral link to analyse.
Query parameters
ParameterTypeRequiredDescription
from string (YYYY-MM-DD) Optional Start of the date range (inclusive). Defaults to 30 days ago.
to string (YYYY-MM-DD) Optional End of the date range (inclusive, up to 23:59:59 UTC). Defaults to today.
Example request
cURL
curl "https://api.linktrace.in/api/v1/analytics/links/497b3422/funnel?from=2026-05-01&to=2026-06-10" \
  -H "x-api-key: lt_live_xxxxxxxxxxxxxxxxxxxx"
Response — 200 OK
FieldTypeDescription
shortCode string The queried short code.
period.from string Resolved start date used for the query.
period.to string Resolved end date used for the query.
funnel.clicks integer Total link clicks in the period.
funnel.attributedInstalls integer App installs attributed to this link in the period.
funnel.clicksByDate array Daily click breakdown: [{ date: "2026-05-01", count: 42 }, ...].
funnel.installsByDate array Daily install breakdown: [{ date: "2026-05-01", count: 7 }, ...].
funnel.events array Scale plan only. Per-event summary: [{ eventName: "purchase", count: 15, conversionFromInstall: 0.68 }, ...]. conversionFromInstall is null when there are no attributed installs. Empty array on non-Scale accounts.
Example response
JSON
{
  "shortCode": "497b3422",
  "period": { "from": "2026-05-01", "to": "2026-06-10" },
  "funnel": {
    "clicks": 1240,
    "attributedInstalls": 312,
    "clicksByDate": [
      { "date": "2026-05-01", "count": 88 },
      // ...
    ],
    "installsByDate": [
      { "date": "2026-05-01", "count": 21 },
      // ...
    ],
    "events": [
      {
        "eventName": "purchase",
        "count": 212,
        "conversionFromInstall": 0.68
      },
      {
        "eventName": "add_to_cart",
        "count": 287,
        "conversionFromInstall": 0.92
      }
    ]
  }
}
400
INVALID_DATE_RANGE from date is after to date.
404
LINK_NOT_FOUND No link with that short code exists for your account.
GET
/api/v1/analytics/events/quota
Returns your current monthly event quota usage, including remaining capacity, warning status, and the reset timestamp.
Scale x-api-key
Example request
cURL
curl https://api.linktrace.in/api/v1/analytics/events/quota \
  -H "x-api-key: lt_live_xxxxxxxxxxxxxxxxxxxx"
Response fields — 200 OK
FieldTypeDescription
plan string Always "scale" for this endpoint.
monthKey string The billing month being measured, e.g. "2026-06".
quota integer Total monthly event allowance. Currently 5,000.
used integer Events ingested so far this month.
remaining integer Events remaining before the quota is exhausted.
percentUsed number Percentage of quota consumed, e.g. 78.40.
nearQuota boolean true when used ≥ 4,000 (80% threshold). Use this to alert your team.
quotaExceeded boolean true when the monthly limit has been fully consumed. Ingestion calls return 429 in this state.
resetsOn string (ISO 8601) UTC timestamp of the 1st of next month, when the quota counter resets to zero.
Monthly event quota 4,000 / 5,000 used
0–3,999: Normal
4,000–4,999: nearQuota: true
5,000+: quotaExceeded: true
Example response
JSON
{
  "plan": "scale",
  "monthKey": "2026-06",
  "quota": 5000,
  "used": 4000,
  "remaining": 1000,
  "percentUsed": 80.00,
  "nearQuota": true,
  "quotaExceeded": false,
  "resetsOn": "2026-07-01T00:00:00.000Z"
}

Link Creation & Attribution

Referral Links and Install Attribution

Create trackable referral links server-side and attribute app installs back to the link that drove them.

POST
/api/v1/referral-links
Create a new trackable referral link. Returns the short URL along with all link metadata.
x-api-key
Request body
FieldTypeRequiredDescription
referrerIdentifier string Required Your internal identifier for the user or entity generating the link (e.g. a user ID). Used to attribute referrals back to a specific referrer.
environment string Optional production (default) or stage. Stage links are excluded from quota counting.
source string Optional Traffic source (e.g. instagram, email). Max 100 chars.
medium string Optional Marketing medium (e.g. story, banner). Max 100 chars.
campaign string Optional Campaign name (e.g. organic_promo_insta). Max 100 chars.
expiryDate string (ISO 8601) Optional Date after which this link should be considered expired (e.g. 2026-12-31).
customPayload object Optional Arbitrary key-value metadata attached to the link and returned in attribution responses. Max 3 keys. Each key: string, max 50 chars. Each value: string (max 200 chars) or number.
Example request
JSON
{
  "referrerIdentifier": "user_id_1234",
  "environment": "production",
  "source": "instagram",
  "medium": "story",
  "campaign": "organic_promo_insta",
  "customPayload": {
    "referral_source": "in_app_referral"
  }
}
Response — 201 Created
FieldTypeDescription
id integer Internal database ID of the link.
shortCode string The 8-character short code (e.g. 497b3422). Use this in event ingestion.
referralLink string (URL) The full shareable URL (e.g. https://app.linktrace.in/r/497b3422). Share this with your users.
referrerIdentifier string Your identifier as provided in the request.
source / medium / campaign string | null UTM-style attribution fields as provided.
environment string production or stage.
expiryDate string | null ISO 8601 date if set, otherwise null.
customPayload object | null The custom metadata as provided.
POST
/api/v1/attributions
Attribute a new app install to the referral link that drove it. Call this once per user, on first launch after install. LinkTrace uses IP fingerprinting to match the install to a prior link click within a 365-day attribution window.
x-api-key
ℹ
How attribution works When a user clicks a referral link, LinkTrace records their IP address. When you call this endpoint with the new user's userId, LinkTrace matches their IP to the most recent unattributed click from the same client account and within the 365-day window. A given userId is only attributed once per client — repeat calls return the existing attribution.
Request body
FieldTypeRequiredDescription
userId string | integer Required Your application's identifier for this newly-installed user. Stored as a string internally.
ipAddress string (IP) Optional Override the IP address used for fingerprint matching. If omitted, LinkTrace uses the IP of the incoming request. Provide this field when your attribution call is proxied through a backend server and you want to pass the end-user's real IP.
Example request
JSON
{
  "userId": 50
}
Response — 200 OK

The response shape is the same whether attribution succeeds or not — always check the attributed boolean first.

FieldTypeDescription
attributed boolean true if a matching click was found and attributed; false if no match.
referrerIdentifier string | null The referrerIdentifier from the matched link. Present when attributed: true.
source string | null Traffic source from the matched link.
medium string | null Marketing medium from the matched link.
campaign string | null Campaign name from the matched link.
customPayload object | null Custom metadata attached to the matched link — use this to pass any data you need at install time.
sourceLinkShortCode string | null The short code of the referral link that was attributed.
Attributed
JSON
{
  "attributed": true,
  "referrerIdentifier": "user_id_1234",
  "source": "instagram",
  "medium": "story",
  "campaign": "organic_promo_insta",
  "customPayload": {
    "referral_source": "in_app_referral"
  },
  "sourceLinkShortCode": "497b3422"
}
Not attributed (no matching click)
JSON
{
  "attributed": false,
  "sourceLinkShortCode": null
}
GET
/api/v1/referral-links/metadata
Resolve metadata for a referral link by full URL, path, or bare short code.
x-api-key
Query parameters
ParameterTypeRequiredDescription
link string Required Accepts any of the following formats:
• Full URL: https://app.linktrace.in/r/497b3422
• Path: /r/497b3422
• Bare short code: 497b3422
Example request
cURL
curl "https://api.linktrace.in/api/v1/referral-links/metadata?link=https://app.linktrace.in/r/497b3422" \
  -H "x-api-key: lt_live_xxxxxxxxxxxxxxxxxxxx"
Response fields — 200 OK
FieldTypeDescription
shortCode string The resolved short code.
referrerIdentifier string The referrer as set when the link was created.
source / medium / campaign string | null UTM-style fields.
environment string production or stage.
customPayload object | null Custom metadata attached to the link.
active boolean Whether the link is currently active.
createdAt string (ISO 8601) Timestamp when the link was created.
⚠
Privacy by design. The API returns an identical 404 Link not found error whether the link does not exist or belongs to a different account — to prevent link enumeration.

Errors

Error Response Format

All errors follow a consistent JSON envelope.

Standard error shape

JSON
{
  "success": false,
  "message": "Human-readable description of what went wrong",
  "code": "MACHINE_READABLE_CODE",   // present on some errors
  "resetsOn": "2026-07-01T00:00:00.000Z" // present on 429 QUOTA_EXCEEDED
}
HTTP Status Code When it occurs
400 — Validation error — missing or invalid request fields.
400 INVALID_DATE_RANGE The from date is after the to date in a funnel query.
403 PLAN_UPGRADE_REQUIRED The requested endpoint requires the Scale plan.
404 LINK_NOT_FOUND The short code does not exist or belongs to another account.
429 QUOTA_EXCEEDED Monthly event quota (5,000) has been exhausted. resetsOn indicates when the counter resets.

Quick start

End-to-end integration in 4 steps

From link creation to conversion analytics.

Step 1 — Create a referral link (server-side)

Generate a unique link for each referrer (user, influencer, campaign).

cURL
curl -X POST https://api.linktrace.in/api/v1/referral-links \
  -H "x-api-key: lt_live_xxxxxxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{ "referrerIdentifier": "user_42", "source": "whatsapp", "campaign": "summer_2026" }'

# Response
{
  "shortCode": "8fa3c12e",
  "referralLink": "https://app.linktrace.in/r/8fa3c12e",
  ...
}

Step 2 — Share the link with the referrer

Return the referralLink URL to your user. They share it through WhatsApp, Instagram, or any other channel. LinkTrace automatically records clicks.

Step 3 — Attribute the install (on first app launch)

On first launch after install, call the attribution endpoint from your backend (or directly from the app) with the new user's ID.

cURL
curl -X POST https://api.linktrace.in/api/v1/attributions \
  -H "x-api-key: lt_live_xxxxxxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{ "userId": "new_user_999", "ipAddress": "203.0.113.42" }'

# If a click match was found
{
  "attributed": true,
  "referrerIdentifier": "user_42",
  "sourceLinkShortCode": "8fa3c12e"
}

Step 4 — Track downstream events (Scale plan)

After install, send custom events whenever the user performs a meaningful action. Use entityId on transactional events like purchases to prevent double-counting.

cURL
curl -X POST https://api.linktrace.in/api/v1/events \
  -H "x-api-key: lt_live_xxxxxxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "linkShortCode": "8fa3c12e",
    "eventName": "first_purchase",
    "entityId": "order_00112"
  }'

Query the funnel at any time to see click → install → event conversion for that link using GET /api/v1/analytics/links/8fa3c12e/funnel.
